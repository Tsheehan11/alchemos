# AlchemOS

A personal desktop: Hyprland on CachyOS (Arch), a Quickshell (QML) HUD, and Orrin, a local voice
assistant that runs through Claude. The full reference is `~/.github/README.md`. Read the relevant
section before changing anything; it documents most of the traps below in detail.

## This is a bare dotfiles repo

- Git dir `~/.alchemos`, work tree `$HOME`. Plain `git` does not work here. Use `alc` (fish
  function) or `git --git-dir=$HOME/.alchemos --work-tree=$HOME`.
- Untracked files are hidden. `alc status` only shows tracked changes; add new files explicitly
  with `alc add <path>`. Never `alc add -A` or `alc add .` (that stages the whole home directory).
- The repo is public (github.com/Tsheehan11/alchemos). Never commit secrets, tokens, API keys,
  real names, emails, IPs, or anything from `~/.ssh` beyond what is already tracked. Test fixtures
  stay generic.
- The LEGACY skin lives in a separate private repo and must not be added here.
- Pushes go straight to `main`. Commit only when asked; never push without being asked.

## Where things are

| Path | What |
| --- | --- |
| `~/.config/hypr/hyprland.lua` + `hypr/alchemos/*.lua` | Hyprland config, split into modules |
| `~/.config/quickshell/` | HUD (QML). `Theme.qml` holds every setting and its default; `skins/<id>/` per skin; `docs/SKINS.md` |
| `~/.config/orrin/` | Assistant: `orrin.py` entry, `core/` (voice loop, router, TTS), `mcp/` (tool servers), `tests/`, `tools/` |
| `~/.config/alchemos-*`, `~/.config/govee/` | Cursor build, combat (game) mode, VPN, Govee lights |
| `~/.local/bin/alchemos-*`, `orrin*` | Commands |
| `~/.config/hypr/system/` | Sources for files installed under `/etc` and `/usr/lib` |

## Hyprland is configured in Lua (0.56+)

The old hyprlang syntax is gone. Do not write `bind = SUPER, Q, killactive`, `hyprctl keyword ...`
or `hyprctl dispatch exec ...`.

- Edit the modules in `hypr/alchemos/` in place: binds in `binds.lua`, window rules in `rules.lua`,
  autostart as an `hl.on("hyprland.start", ...)` block in `autostart.lua`. Saving reloads Hyprland.
- Never replace `hyprland.lua`; it is only the loader.
- `alchemos/display-profile.lua` is generated by the HUD. Do not edit or track it.
- Runtime: `hyprctl eval 'hl.config({...})'`, `hyprctl dispatch 'hl.dsp.exec_cmd("kitty")'`. In QML,
  build these through `quickshell/Hypr.js`.
- API stubs: `/usr/share/hypr/stubs`. Check them instead of guessing a function name.
- After a config edit run `hyprctl configerrors` (or `alchemos-hypr-check`) and fix what it lists.

## HUD (Quickshell)

- Settings are saved in `~/.config/quickshell/settings.json`; read or set them with
  `qs ipc call theme get|set <key> [value]`. A new setting needs its default in `Theme.qml`.
- Screens are addressed by role (main / diag / media, from `Roles.qml`), never by port name.
- A theme change fans out to Hyprland borders, lock pictures, kitty, VS Code, cursor and Govee.
  Go through `Theme.qml`; do not recolour one target on its own.
- Generated files, not tracked and not edited by hand: `hypr/hyprlock.conf`,
  `hypr/alchemos-lock-bg-*`, `kitty/alchemos-theme.conf`, `govee/theme.json`,
  `quickshell/widgets.json`. Edit the template or the generator.
- Looks belong in the skin (`skins/<id>/`), shared behaviour in the common QML. See `docs/SKINS.md`.

## Orrin

- Python 3.11 in `~/.config/orrin/.venv` (managed with `uv`). Runs as the user service
  `orrin.service`, controlled with `orrinctl`. Logs: `journalctl --user -u orrin`.
- One assistant with two personas (Orrin, Selene): same brain, tools and memory. Keep changes
  working for both.
- New capabilities are MCP servers registered in `servers.json`; the core loop should not change.
  Reads can be auto-allowed; anything that writes or sends needs a spoken confirmation.
- Tests: one suite with `.venv/bin/python tests/test_<name>.py`, everything with
  `tools/check_all.sh` (a few minutes; add `-q` for failures only). The router eval must report
  0 wrong actions at threshold 0.70. A router or intent change needs matching eval cases.

## Checks and the pre-commit hook

- Staging anything under `.config/orrin/` runs `tools/check_all.sh`; staging HUD files runs
  `quickshell/tools/skincheck/check_skins.sh` (needs a Wayland session).
- Never use `--no-verify`. If a suite is red, fix the cause. Do not weaken, skip or delete a test,
  and do not regenerate the LEGACY baseline to make the skin check pass.
- Run the relevant check yourself before reporting done, and report the result.

## Do not do without asking

- Anything needing `sudo`, or touching `/etc`, `/usr/lib`, PAM, faillock or logind. Those are
  installed from `hypr/system/` by `hypr/fprint-install.fish`; change the source and tell the user
  to run the installer.
- Kill or restart `fprintd` or `hyprlock`, lock the session, or suspend. A wedged fingerprint
  reader needs a power-off. Recovery is `alchemos-rescue` from a TTY.
- `hyprctl reload`, restarting `qs`, or logging out mid-task without warning: it is his live desktop
  and it drops runtime state.
- Install or remove packages, or enable services at boot.

## Style

- Names use `alchemos-*` and Orrin. The old `stark-*` / Jarvis names survive only as compatibility
  aliases; do not add new ones.
- Comments and README text: plain sentences, no first names or personal details.
- Update `~/.github/README.md` in the same commit when behaviour, a keybind or a setting changes.
